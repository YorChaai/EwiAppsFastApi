# Halaman Register (PRD Ringkas)

Halaman Register memiliki antarmuka adaptif (_responsive layout_ untuk _Compact, Mobile, Tablet_, dan _Landscape Intro Panel_ khusus layar besar) bergaya _Card Container_ dengan dukungan _Theme-aware UI_ (Mode Gelap/Terang). Pengguna diwajibkan mengisi input **Username** dan **Nama Lengkap** (divalidasi tidak boleh kosong). Jika pengguna mendaftar melalui Single Sign-On (SSO) Google, sistem akan otomatis mengisi (_pre-populate_) Email, Nama, dan Google ID; di mana khusus skenario ini, kolom **Email** akan terkunci (_read-only_) dan divalidasi wajib terisi. Sementara untuk pendaftaran manual, input email akan divalidasi formatnya (wajib mengandung '@'). Terdapat juga tombol navigasi "Kembali" untuk membatalkan proses.

Selanjutnya, pengguna dihadapkan pada kolom **No Handphone** dan **Tempat Kerja** yang bersifat opsional; jika dikosongkan, sistem otomatis menyisipkan nilai '-' ke _backend_. Untuk keamanan, input **Password** dan **Konfirmasi Password** (keduanya dilengkapi fitur _Toggle Visibility_ ikon mata) wajib diisi minimal 6 karakter dan divalidasi harus sama persis. Pengguna juga dapat memilih pengaturan akses melalui menu _dropdown_, yaitu peran (_Role_ bawaan: 'staff') dan instansi (_Company_ bawaan: 'EWI Foundation' yang opsinya diambil secara dinamis dari data pusat sistem).

Saat tombol utama "Daftar" ditekan, semua validasi form akan dieksekusi secara lokal. Jika gagal atau ditolak server (misal _username_ terpakai), pesan _error_ spesifik akan muncul pada peringatan global (_Snackbar_) berwarna merah di bawah layar. Sebaliknya, jika berhasil, sebuah _Success Dialog Popup_ interaktif dengan animasi centang hijau akan muncul. Teks pesan sukses ini beradaptasi secara cerdas: pengguna SSO Google diinfokan dapat _login_ menggunakan Gmail maupun _username_ reguler, sedangkan pendaftar manual diinstruksikan untuk _login_ dengan akun barunya. Sebagai perbaikan _bug_ (penundaan transisi), ketika tombol "OK, Login Sekarang" pada _dialog_ sukses ditekan, sistem dengan sengaja memberikan _delay_ 300 milidetik sebelum mengembalikan pengguna ke halaman Login secara mulus untuk mencegah layar menjadi kosong (_blank_).
